# NOD-SBC-001 — ED-03 Quantitative Power Budget & Power-Tree Design

**Baseline:** Rev A electrical-design increment  
**Status:** Preliminary engineering allocation; regulator/P/N selection pending measured load and final SoM configuration

## 1. Purpose

ED-03 converts the ED-01/ED-02 compute architecture into a quantitative preliminary power envelope and carrier-level power-tree architecture.

The design must support:

- i.MX 95 application-processing SoM baseline
- STM32H573-class mandatory management MCU
- optional Lattice Avant-E FPGA population
- high-performance FPGA variant without forcing that power burden onto the common carrier
- NVMe/storage, Ethernet, USB, mission I/O, sensors, and optional RF/display loads
- battery and external/vehicle power integration through a protected front end

This document establishes **engineering allocations**, not final device ratings. Actual regulator sizing and thermal qualification shall use vendor data, selected SoM characterization, and measured prototype loads.

## 2. Power-Architecture Decision

Use a protected wide-input front end feeding a carrier system bus, followed by synchronous buck conversion to the principal carrier rails.

```text
       EXT / VEHICLE INPUT
              │
       [Fuse / eFuse]
              │
 [OV / UV / Reverse Polarity]
              │
      [Surge / TVS Clamp]
              │
       [Ideal-Diode OR]
          ┌───┴───┐
          │       │
       EXT-IN   VBAT-IN
          │       │
          └───┬───┘
              │
        PROTECTED_SYS_BUS
              │
      ┌───────┼───────────┐
      │       │           │
    BUCK    BUCK        LOAD SWITCHES
      │       │           │
     5V     3V3      USB / RF / AUX
      │       │
 ┌────┼──┐ ┌─┼───────────────┐
 │    │  │ │ │               │
SoM  USB NVMe MCU/Ethernet  FPGA*
 │
 └── SoM-local PMIC / core rails

* Optional population; high-performance FPGA variant uses its own dedicated
  high-current rail set and clock/reset sequencing.
```

### Architectural rules

1. The carrier shall not recreate processor-core rails already generated by the selected SoM.
2. High-current loads receive dedicated regulators or load switches rather than sharing sensitive analog rails.
3. RF and sensor supplies shall be separately switchable and, where required, post-filtered.
4. The STM32H573 supervises power-good, sequencing, thermal limits, brownout, and controlled shutdown.
5. Every externally accessible power output is current-limited and software-monitored where practical.
6. The FPGA is electrically optional; the baseline board must remain functional with the FPGA unpopulated.

## 3. Preliminary Power Budget

The following values are **design allocations**, not measured silicon specifications.

| Load domain | Typical allocation | Continuous design envelope | Notes |
|---|---:|---:|---|
| i.MX 95 SoM + LPDDR5/configuration | 8.0 W | 12.0 W | Final value depends on SoM SKU, memory, clocks, workload, and thermal mode |
| STM32H573 management MCU | 0.25 W | 0.50 W | Includes management peripherals and supervisory I/O allocation |
| NVMe / local storage | 2.0 W | 5.0 W | Depends strongly on module and workload |
| Ethernet PHY/switching | 1.0 W | 2.0 W | Allocation for carrier networking |
| USB / external digital I/O | 1.0 W | 3.0 W | Includes externally delivered VBUS power where populated |
| RF / mission-module power | 2.0 W | 6.0 W | Mission-dependent; externally populated loads shall be budgeted separately |
| Sensors / timing / GNSS | 0.25 W | 1.0 W | Carrier-side allocation |
| Optional FPGA | 2.0 W | 5.0 W | E30/E50-class preliminary allocation; final value requires implementation/activity analysis |
| Display / HMI interface | 1.0 W | 2.5 W | Optional carrier/system load, not required for headless SBC |
| Carrier overhead / conversion margin | 1.0 W | 2.5 W | Clocking, monitors, LEDs, losses, miscellaneous |

### 3.1 Baseline population

For the common Rev-A carrier, omit the optional FPGA and optional display from the mandatory board budget.

**Nominal baseline allocation:** approximately **15.5 W** including the carrier-overhead allocation.

**Preliminary continuous envelope:** approximately **27.0 W** before optional RF/display loads are simultaneously maximized.

The envelope is intentionally conservative and shall be reduced after prototype characterization.

### 3.2 Expanded mission population

With optional FPGA, display, and high RF activity simultaneously populated, the preliminary system envelope can approach **32 W**.

This is a **variant-class design ceiling**, not a claim that every NOD-SBC-001 configuration consumes 32 W.

## 4. Input-Power Allocation

The common architecture shall reserve the front end for:

- protected external/vehicle input
- protected battery input
- automatic source selection / ideal-diode ORing
- input current limiting
- reverse-polarity protection
- over-voltage / under-voltage shutdown
- transient/surge suppression
- input-voltage and input-current telemetry

The exact battery chemistry and raw input range remain **TBD** at ED-03 because the Nodem handheld, Micro-ManPack, vehicle, and fixed-node variants may use different source assemblies.

A **9–36 V external-input candidate range** is retained as an engineering option for vehicle/fixed installations, but it is **not frozen as the production electrical requirement** by this document.

## 6. Preliminary Regulator Strategy

### Stage A — Input protection

Provide:

- fuse/eFuse or resettable protection
- reverse-polarity protection
- TVS transient clamp sized for the final source environment
- UVLO/OVLO
- inrush-current control
- input current/voltage monitor

### Stage B — Main conversion

Use synchronous buck conversion from the protected system bus to +5V_MAIN and +3V3_MAIN.

Initial engineering efficiency assumption:

- main buck stages: **90–95%** across the expected operating region
- low-current post-regulators/LDOs: sized by dropout and noise requirements rather than nominal efficiency alone

These are **design assumptions** and shall be replaced by selected-regulator efficiency curves during ED-04 component selection.

### Stage C — Load switching

Use individually controllable load switches/eFuses for:

- USB VBUS
- RF/mission modules
- display/HMI
- optional FPGA subsystem
- externally accessible auxiliary power

The STM32H573 owns enable sequencing and fault reporting.

## 7. Power Sequencing

```text
VIN VALID
   │
   ▼
INPUT PROTECTION PASS
   │
   ▼
SYS_BUS VALID
   │
   ▼
3V3_MAIN / 5V_MAIN ENABLE
   │
   ▼
MCU POWER-GOOD
   │
   ▼
STM32H573 BOOT
   │
   ├── verify input/thermal/fault state
   ├── enable SoM rail / release SoM reset
   ├── enable storage/network peripherals
   └── enable optional FPGA / mission loads
              │
              ▼
        APPLICATION READY
```

Shutdown shall reverse the dependency order: mission peripherals first, application SoM next, management MCU last.

Brownout or thermal-fault handling shall default to disabling nonessential mission loads before removing the application domain.

## 8. Thermal Allocation

Carrier thermal design shall use:

`P_loss = P_load × (1/η − 1)`

for each switching stage, plus regulator quiescent losses and local component losses.

The board shall therefore be evaluated in three thermal classes:

| Thermal class | Board dissipation | Intended use |
|---|---:|---|
| T1 | ≤10 W | low-power/headless configurations |
| T2 | >10 W to 20 W | common mission SBC configurations |
| T3 | >20 W | FPGA/RF/high-throughput variants |

The Nodem mechanical thermal path remains:

`hot component → local copper spreader → aluminum structural spine → side heat rails → external chassis surface/fins → ambient`

The 160 × 100 mm PCB target remains provisional until ED-04 thermal and regulator placement analysis is complete.

## 9. Power Monitoring Requirements

At minimum measure:

- raw input voltage
- protected system-bus voltage
- protected system-bus current
- +5V_MAIN current
- +3V3_MAIN current
- FPGA subsystem current when populated
- board temperature
- SoM thermal telemetry through software interface

The STM32H573 shall expose a deterministic health record to Nodem-SBC-OS containing:

- rail state
- power-good state
- current-limit/fault state
- thermal state
- brownout history
- controlled shutdown reason
- boot/recovery status

## 10. Power Integrity Requirements

ED-03 establishes the following preliminary PI rules:

1. Separate high-di/dt converter loops from sensitive clock/RF/sensor areas.
2. Place input/output ceramic capacitance at every regulator according to the selected regulator datasheet.
3. Use dedicated planes for high-current rails where PCB stackup permits.
4. Keep FPGA and SoM high-speed power distribution physically compact.
5. Use ferrite/LC filtering only where impedance and transient response are verified; do not insert arbitrary ferrites into high-current processor rails.
6. Define PDN impedance targets during ED-04/ED-05 after actual load transient requirements are known.

## 11. Design Margins

Regulator and connector sizing shall not be based on nominal load alone.

Preliminary rules:

- regulator continuous rating: **≥125%** of calculated continuous load
- connector/pin continuous rating: **≥125%** of expected continuous current
- transient headroom: **≥25%** above modeled load-step requirement before current limiting
- thermal design shall be evaluated at worst permitted ambient, not room temperature only

Final margins shall be reconciled against selected component derating curves and environmental requirements.
